# 上下文最小化：按需读文件

项目为 Rust(Tauri 2.x) + 原生前端。任何任务开始前必须遵守以下流程，最小化文件读取、降低上下文与限流消耗：

1. 先读 README.md 的「目录结构」段，确认目标改动落在哪个模块。
2. 功能点与开关对应关系查 FEATURES.md；开关统一注册在 src-tauri/src/config/feature_flags.rs。
3. 定位代码一律优先用 Grep / Glob / SearchCodebase 按符号名搜索，禁止一次性 Read 整个目录。
4. 只读与本次改动直接相关的文件：
   - 改可插拔模块：只读 src-tauri/src/modules/<模块>/ 下文件 + 其 command 注册处（lib.rs 的 invoke_handler / 该模块 commands.rs）。
   - 改 SSH 核心：只读 src-tauri/src/ssh/ 下相关文件。
   - 改前端：只读 src/js/<对应>.js 及可能涉及的 styles/。
5. 仅在新增功能时更新 FEATURES.md 登记，结构变动时更新 README.md 目录结构。

# 敏感信息隔离（强制）

必须保证代码里没有个人账号信息和个人配置信息的内容：

1. 严禁在源码、注释、测试、示例、文档、日志中硬编码任何个人账号信息（用户名、密码、token、密钥、邮箱、私钥等）或个人配置信息（主机 IP、路径、端口、API Key、个人偏好配置等）。
2. 个人账号信息和个人配置信息必须放在独立的配置文件中（如本地 profile / env / 用户配置目录），与代码仓库分离。
3. 这些配置文件必须写入 .gitignore，确保绝对不会随 git 一起提交到远程代码仓库；提交前必须确认 `git status` 中不含此类文件。
4. 代码中只允许通过占位符、环境变量或配置读取接口引用，不得出现真实值。
5. 任何可能被提交（含新增、修改、历史遗留）的代码都不得暴露个人敏感信息：提交前必须自查源码、注释、测试、示例、文档、日志及 Git 历史，确认不含真实账号、口令、token、密钥、私钥、邮箱、主机 IP 等；发现即先清理再提交，严禁将敏感信息推送到远程仓库。
